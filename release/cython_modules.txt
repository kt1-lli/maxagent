# 已知问题（2026-05-25）：
# - tools/registry.py **不能** 走 Cython。原因：该文件提供 @tool 装饰器，
#   会在每个工具模块（scene_query / geometry / ...）import 阶段被多次
#   调用，内部再用 inspect.signature(func) 反射用户函数。
#   即便启用了 binding=True + embedsignature=True，Cython 编译后的
#   <cyfunction tool> 在 3ds Max 嵌入 Python (3.11.x) 环境里反射纯
#   .pyc 函数时仍会触发 C 层崩溃（Max 桥接报 "Unknown exception"，
#   Python try/except 无法拦截）。
#   该问题在 Linux 沙箱 + 系统 CPython 上不复现，仅在 Max 嵌入解释器
#   触发，疑似 cyfunction frame 与 CPython frame 跨边界访问的环境
#   敏感问题。registry.py 是纯框架代码（装饰器 + JSON Schema 推导），
#   不含敏感逻辑或密钥，明文 .pyc 兜底无安全损失。
#
# 已知问题（2026-05-28）：
# - agent/worker.py **不能** 走 Cython。现象：mzp 包安装到 Max 后，
#   UI 能正常显示，但点击发送按钮后业务链路无任何反应（ui_send 日志
#   能打出，后续 worker / LLM / chunk 全部无日志），UI 主线程不卡，
#   只是消息送出后无回应。源码直接 fileIn 运行完全正常。
#   根因：worker.py 含 14 处 PySide Signal/Slot 与 QThread 跨线程调用，
#   Cython 编译产物在 Max 嵌入解释器里 emit 信号时疑似命中与 registry.py
#   类似的 cyfunction frame 跨边界异常，被 Qt 异常分发层吞掉无法拦截。
#   worker.py 是纯调度逻辑（无 API key / 无 system prompt 字面量，
#   核心 prompt 在 agent/conversation.py 中维护），改走 PyArmor L2
#   保护无安全损失。
